# Campus Knowledge Hub frontend

The frontend is a React application served independently by Vite. The backend API uses MongoDB Atlas.

## Run locally

Use Node.js 22.13 or newer and start the backend and frontend in separate terminals.

Terminal 1:

```powershell
cd backend
npm run dev
```

The backend listens at `http://localhost:5001`.

Terminal 2:

```powershell
cd frontend
npm run dev
```

Open `http://localhost:5173`. Vite proxies `/api` requests to the backend. The frontend can also call the backend directly through `VITE_API_URL`.

## Environment configuration

Set `VITE_GOOGLE_CLIENT_ID` in `frontend/.env` and use the same Web application client ID as `GOOGLE_CLIENT_ID` in `backend/.env`. Set `VITE_API_URL=http://localhost:5001` for direct API requests (or use `/api` to go through Vite's proxy). Keep MongoDB URI and JWT secrets only in `backend/.env`.

In Google Cloud Console, add `http://localhost:5173` as an Authorized JavaScript origin. Google sign-in uses the popup flow; no redirect URI is needed. If the OAuth consent screen is in Testing mode, add the sign-in account as a test user.

New Google registrations receive the Student role. Existing accounts are matched by verified email; existing administrator roles are preserved. Authentication currently uses revocable bearer sessions with JWTs held by the existing frontend auth state. HttpOnly cookies would require migrating both student and admin auth contexts and their session restoration flow, so they are not enabled by this change.

## Build

```powershell
cd frontend
npm run build
```

For production, build the frontend and start the backend with `NODE_ENV=production`; the backend serves the generated `frontend/dist` files.

## Deploy on Render

The root `render.yaml` defines one Node web service. Create it as a Render Blueprint from the repository root, leave Root Directory blank, and use the Blueprint's build and start commands. Render prompts for `MONGODB_URI`, `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD`, `GOOGLE_CLIENT_ID`, and `VITE_GOOGLE_CLIENT_ID`; `JWT_SECRET` is generated by Render. Use the same Google Web client ID for the backend and frontend variables. The build sets `VITE_API_URL=/api`, so the deployed frontend sends requests to the backend on the same Render domain.

In MongoDB Atlas, allow connections from the Render service (Atlas Network Access). Once Render assigns the service URL, add its origin (for example, `https://your-service.onrender.com`) to the Google OAuth client's Authorized JavaScript origins. If using Google Meet creation, enable Google Calendar API and add the deployed origin to the OAuth consent configuration as well.
